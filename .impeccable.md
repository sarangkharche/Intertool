## Design Context

### Users

Intertool is used by developer-platform, AI enablement, and governance teams that need to publish, review, discover, and install approved agent capabilities. The interface should help them understand registry state quickly and complete operational tasks with confidence.

### Brand Personality

Calm, precise, and trustworthy. Intertool should feel like focused developer infrastructure: technically credible and quietly polished, without visual noise or novelty that competes with the work.

### Aesthetic Direction

Use the existing refined, utilitarian design language: Newsreader Regular for public landing-page display headings, Geist for UI and body text, Geist Mono for technical identifiers, warm OKLCH surfaces, restrained blue accents for links, focus, and active states, neutral filled buttons, compact controls, clear separators, and purposeful motion. Support both light and dark themes. Avoid generic dashboard ornament, decorative gradients, glass effects, oversized metrics, and unnecessary card nesting.

Typography stays at interface scale throughout the product. Product headings use Geist at `text-lg font-medium tracking-tight` (18px/500), while the public landing page may use Newsreader Regular at its established display scale for the hero and major section statements. Supporting copy remains Geist; controls never use the display face.

### Design Principles

1. Make registry status and the next useful action obvious.
2. Preserve information density without making the interface feel cramped.
3. Use motion only to explain progress or state changes, and respect reduced-motion preferences.
4. Build with semantic HTML, accessible names, visible focus states, and sufficient contrast.
5. Reuse the shared tokens and primitives so every surface feels native to Intertool.
